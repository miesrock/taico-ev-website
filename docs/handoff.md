# TAICO EV 独立站项目 Handoff

以下内容可直接交给 Codex、新对话或外部开发人员，作为项目启动上下文。

---

## 1. 项目背景

TAICO 已购买独立域名：

```text
taicoev.com
```

TAICO 准备采用小夫充电的相关技术和产品进行 OEM，以 TAICO 品牌面向海外市场销售移动充电、储能充电及光储充产品。

现有参考资料：

```text
TAICO_Mobile_Charging_Strategy.md
2026年小夫充电画册新版6.1pdf(1)(1).pdf
小夫产品应用及案例(1).pdf
```

TAICO 原有网站 `taicopower.com` 主要面向：

- 储能电池经销商
    
- 光伏安装商
    
- 储能 EPC
    
- 电池及逆变器客户
    

而 `taicoev.com` 面向的是一批明显不同的客户：

- 汽车经销商和 4S 店
    
- 道路救援和保险服务商
    
- 充电运营商
    
- 酒店、商场、停车场和物业
    
- 车队及物流运营商
    
- 工程机械、矿山、港口和施工企业
    
- 偏远地区、农业及离网应用客户
    

因此，`taicoev.com` 应作为相对独立的 EV 能源解决方案品牌站建设，而不是简单放在 TAICO Power 官网下面作为一个产品分类。

# 2. 核心战略定位

## 品牌定位

推荐定位：

> **TAICO EV provides mobile energy solutions for electric mobility beyond the grid.**

中文含义：

> TAICO EV 为受电网、场地和基础设施限制的商业客户，提供灵活部署的移动充电与能源解决方案。

首页可使用的品牌主张：

```text
Power Electric Mobility Beyond the Grid.
```

或：

```text
Charge Anywhere.
Deploy EV Charging Without Waiting for Grid Expansion.
```

## 不应采用的定位

不要把网站做成：

```text
Mobile EV Charger Manufacturer
```

也不要做成单纯的产品型号目录。

这样会直接进入中国充电设备厂商之间的参数与价格竞争。

网站真正需要销售的是：

- 无需或减少电网扩容
    
- 缩短部署时间
    
- 应对临时和高峰充电需求
    
- 将充电服务移动到客户所在位置
    
- 提升车辆、场地和设备利用率
    
- 创造新的服务和运营收入

# 3. 核心客户优先级

## 第一优先级：汽车经销商和 4S 店

客户痛点：

- 试驾车、展车和交付车辆需要及时补电
    
- 门店固定充电位不足
    
- 电网容量有限
    
- 新建固定充电设施周期长
    
- 希望改善 EV 客户体验
    
- 希望增加售后和会员服务收入
    

网站表达重点：

> 不只是销售一台充电设备，而是帮助经销商建立移动充电服务能力。

对应页面：

```text
/solutions/ev-dealership-charging/
```

核心价值：

- 试驾车辆快速补能
    
- 新车交付保障
    
- 售后应急充电
    
- 上门充电服务
    
- 差异化客户体验
    
- 会员和增值服务模式
    

---

## 第二优先级：道路救援与汽车服务

目标客户：

- 道路救援公司
    
- 拖车公司
    
- 保险公司
    
- 汽车服务平台
    
- EV 充电服务运营商
    

核心信息：

```text
Bring Fast Charging Directly to Stranded EV Drivers.
```

价值：

- 减少不必要的拖车
    
- 提高救援响应效率
    
- 改善车主体验
    
- 支持按次、会员或包年服务模式
    

对应页面：

```text
/solutions/ev-roadside-assistance/
```

---

## 第三优先级：无需电网扩容的商业充电

目标客户：

- 商场
    
- 酒店
    
- 商业停车场
    
- 地产物业
    
- 景区和度假村
    
- 充电站运营商
    

核心问题：

> 有 EV 充电需求，但固定充电基础设施建设太慢、太贵或电网容量不足。

对应页面：

```text
/solutions/ev-charging-without-grid-upgrade/
```

核心关键词：

```text
EV charging without grid upgrade
battery-powered EV charging
temporary EV charging station
mobile EV charging solution
```

---

## 后续高客单市场

第二阶段或第三阶段再重点建设：

- 车队与物流充电
    
- 工程机械移动补能
    
- 矿山和港口
    
- 农业与偏远场景
    
- 光储充一体化
    
- 大型应急能源保障
    

不应在第一版首页把所有场景平铺，否则品牌定位会失焦。

# 4. 产品线展示原则

现有产品覆盖范围较大，包括：

- G2V 便携或移动快充产品
    
- XF-7560 等移动储能充电设备
    
- X200120 多功能移动储能电站
    
- X400360 大型工程机械移动补能设备
    
- F200120 光储充一体化产品
    
- T1000480 兆瓦级移动能源设备
    

第一版网站不应把所有型号同等展示。

## 第一阶段建议重点产品

### 1. G2V

主要面向：

- 4S 店
    
- 商业停车场
    
- 固定充电站补位
    
- 临时活动
    
- 轻量化商业充电
    

### 2. XF-7560 或相近中型移动充电产品

主要面向：

- 道路救援
    
- 上门充电
    
- 高端汽车服务
    
- 酒店、会所和物业
    
- 移动充电运营商
    

### 3. X200120 或 F200120

作为更大型解决方案入口：

- 弱电网商业场所
    
- 光储充
    
- 加油站升级
    
- 工商业园区
    
- 偏远或临时项目
    

X400360、T1000480 等大型产品可先保留为工程和定制项目能力展示，不作为第一版首页的主要获客入口。

# 7. SEO 与 GEO 设计原则

## 核心原则

网站不应通过 AI 批量生成大量相似国家页或垃圾 SEO 页面。

第一阶段优先做约 15–20 个高质量页面。

页面应围绕真实购买意图：

```text
EV charging solution for dealerships
mobile EV roadside assistance charger
EV charging without grid upgrade
temporary EV charging for commercial parking
battery-powered EV charging station
mobile charging for electric fleets
```

## 内容类型

### 商业解决方案页面

例如：

```text
/solutions/ev-dealership-charging/
/solutions/ev-roadside-assistance/
/solutions/ev-charging-without-grid-upgrade/
```

### 技术问题页面

例如：

```text
/resources/how-to-deploy-ev-charging-without-grid-upgrade/
/resources/mobile-vs-fixed-ev-charging/
/resources/how-car-dealerships-can-use-mobile-ev-charging/
```

### 产品页面

每个页面必须同时解释：

- 产品是什么
    
- 最适合谁
    
- 解决什么问题
    
- 适用场景
    
- 部署条件
    
- 技术参数
    
- 接口和兼容性
    
- 认证状态
    
- 如何询价
    

不能只有参数表。

## 技术 SEO

第一版必须包括：

- 唯一的 title
    
- meta description
    
- canonical
    
- sitemap.xml
    
- robots.txt
    
- Open Graph
    
- 合理的 H1/H2 结构
    
- 图片 alt
    
- 内链
    
- 404 页面
    
- 重定向规则
    
- 页面性能检查
    

## GEO

应增加：

- Organization Schema
    
- Product Schema
    
- FAQ Schema
    
- Breadcrumb Schema
    
- 结构化的公司、产品和应用关系
    
- `/llms.txt`
    
- 清晰、可引用的事实性说明
    
- 作者或公司责任主体
    
- 案例来源和日期
    
- 可验证的认证与技术参数

# 8. 推荐技术栈

## 第一阶段推荐

```text
Astro
+ TypeScript
+ Tailwind CSS
+ Astro Content Collections
+ Markdown / MDX
+ GitHub
+ Cloudflare Pages
+ Cloudflare DNS/CDN
+ Playwright
```

## 各组件作用

### Astro

负责网站页面、组件和静态构建。

适合：

- B2B 企业站
    
- 解决方案页面
    
- 产品页
    
- 案例
    
- 内容营销
    
- SEO/GEO
    

优点：

- 默认输出 HTML
    
- 页面加载快
    
- JavaScript 负担低
    
- 适合内容型网站
    
- 易于通过 Codex 维护
    

### TypeScript

用于增强数据结构和代码可靠性。

适合定义：

- 产品参数
    
- 页面元数据
    
- 多语言字段
    
- Schema
    
- 表单数据
    

### Tailwind CSS

用于建立统一设计系统，并便于 Codex 修改布局和样式。

必须先定义：

- 字体
    
- 间距
    
- 容器宽度
    
- 按钮
    
- 卡片
    
- 表格
    
- CTA
    
- 移动端规则
    

不能让 Codex 每个页面自行设计。

### Astro Content Collections

用于结构化管理：

- 产品
    
- 解决方案
    
- 案例
    
- 文章
    
- FAQ
    

例如：

```text
src/content/products/
src/content/solutions/
src/content/cases/
src/content/resources/
```

### GitHub

用于：

- 版本管理
    
- 代码审查
    
- 回滚
    
- 多人协作
    
- 触发自动部署
    
- 保存项目文档和知识库
    

### Cloudflare Pages

用于：

- 自动部署
    
- 全球 CDN
    
- HTTPS
    
- 预览环境
    
- 较低运维成本
    

网站发布流程：

```text
本地修改
→ Git commit
→ Push to GitHub
→ Cloudflare自动构建
→ 生成预览或正式版本
```

### Cloudflare DNS

负责把：

```text
taicoev.com
```

指向 Cloudflare Pages。

同时管理：

- A/CNAME 记录
    
- HTTPS
    
- CDN
    
- 缓存
    
- 安全规则
    
- 邮箱相关 DNS 记录
    

### Playwright

用于自动测试：

- 页面是否正常打开
    
- 是否出现 404
    
- 导航链接是否有效
    
- 图片是否加载
    
- 表单能否提交
    
- 移动端布局
    
- 多浏览器测试
    
- 页面截图回归

# 9. 为什么不优先选择其他方案

## WordPress

适合老板和销售频繁使用后台编辑内容。

问题：

- 插件依赖较多
    
- 长期维护和安全成本更高
    
- 代码、内容和数据容易分散
    
- Codex 自动化能力不如代码仓库路线完整
    

如果未来多人需要后台编辑，可以引入 CMS，而不是第一天就使用 WordPress。

## Webflow

优点：

- 设计成熟
    
- CMS 直观
    
- 海外访问和托管方便
    

不足：

- 平台绑定较强
    
- 批量内容和自动化控制能力有限
    
- Codex 无法完全管理整个系统
    
- 长期内容资产可移植性较弱
    

## Framer

适合快速品牌落地页，但不适合作为长期 B2B 内容、产品、案例和 SEO 知识库。

## Next.js

功能强，但当前阶段过重。

只有未来需要以下功能时再考虑：

- 用户登录
    
- 经销商门户
    
- 在线报价
    
- 动态配置器
    
- 客户项目管理
    
- 复杂数据库
    
- AI 方案生成平台
    

第一阶段 Astro 足够。

# 12. Codex 工作原则

在根目录建立 `AGENTS.md`，至少包含以下规则：

```text
1. 禁止编造产品参数、认证、客户案例、兼容性、收益和部署结果。
2. 所有产品数据必须来自 knowledge-base/products。
3. 不确定的信息必须标记为 TBD 或 Needs Verification。
4. 不直接复制小夫或竞争对手的网页文案。
5. TAICO 对外品牌为 TAICO EV，小夫仅作为 OEM 技术来源，不作为主要品牌展示。
6. Solution 页面优先于 Product 页面。
7. 所有页面必须响应式，并通过移动端检查。
8. 所有公开页面必须有 title、description、canonical 和合理标题结构。
9. 每次修改后运行 build、lint、链接检查和 Playwright 测试。
10. 禁止未经验证使用“降低90%成本”“缩短25%工期”等具体营销数字。
11. 认证、接口、温度范围和防护等级必须对应具体型号。
12. 图片必须确认商业使用权，不使用来历不明素材。
13. 提交代码时说明修改内容、验证方式和潜在风险。
14. 每一步工程配置都同步写入 docs，形成可复用技能文档。
```

```text
域名
→ DNS
→ GitHub
→ Astro
→ 本地开发
→ Cloudflare部署
→ HTTPS
→ SEO/GEO检查
```

1. 操作步骤
    
2. 核心概念
    
3. 常见错误
    
4. 排查方式
    
5. 可复用模板
    
6. Codex 提示词
    
7. 验收清单
    

最终形成可复用技能：

> 独立完成面向海外市场的 B2B 企业站定位、开发、部署、SEO/GEO 和自动化维护。

# 15. 询盘系统

不要只使用：

```text
Name
Email
Message
```

建议表单收集：

```text
Country
Company name
Company type
Application
Vehicle or equipment type
Number of vehicles
Required charging power
Current grid capacity
Deployment location
Expected timeline
Message
```

根据客户类型动态增加字段：

## Dealership

- Number of dealerships
    
- EV brands represented
    
- Number of delivery/test-drive vehicles
    
- Existing charger availability
    

## Fleet

- Fleet size
    
- Vehicle type
    
- Daily mileage
    
- Parking pattern
    
- Charging window
    

## Industrial

- Equipment type
    
- Required voltage and power
    
- Daily operating hours
    
- Grid or off-grid conditions
    

表单数据后续可进入：

- 邮箱
    
- Google Sheet
    
- OKKI
    
- Zoho CRM
    
- 自建销售 Agent

## Phase 1：知识库

把 PDF 和现有资料整理为结构化 Markdown 或 JSON。

不让 Codex 每次直接从 PDF 临时理解。

## Phase 2：技术链路最小验证

先只建一个测试首页，跑通：

```text
本地 Astro
→ GitHub
→ Cloudflare Pages
→ 临时 pages.dev 地址
→ 自定义域名
→ HTTPS
```

这一阶段重点是学习工程链路，不追求完整视觉。

## Phase 3：设计系统和核心页面

完成：

- Header
    
- Footer
    
- Button
    
- Card
    
- Product specification table
    
- Case study component
    
- CTA
    
- Form
    
- Responsive layout
    

## Phase 4：第一版内容上线

发布约 15–20 个经过核实的页面。

## Phase 5：SEO/GEO 和测试

完成：

- Sitemap
    
- Robots
    
- Schema
    
- Search Console
    
- Analytics
    
- Lighthouse
    
- Playwright
    
- 404 和链接检查

打通：

```text
客户开发邮件
→ 对应 Landing Page

→ AI 判断客户类型和推荐产品

```

# 17. 开工前仍需老板确认的问题

以下问题没有确认前，不应大规模写页面：

1. `TAICO EV` 是正式子品牌，还是仅作为 TAICO Power 产品线名称？
    
2. Logo 是否沿用 TAICO Power，还是有独立 EV 版本？
    
3. 第一阶段主推 G2V、移动储能充电，还是大型光储充？
    
4. 优先市场是澳洲、中东、欧洲还是其他地区？
    
5. 哪些小夫案例可以由 TAICO 对外公开使用？
    
6. 是否可以公开客户国家、品牌和现场照片？
    
7. OEM 后的正式产品型号是什么？
    
8. 哪些认证已经取得，哪些仍需申请？
    
9. TAICO 与小夫的品牌和制造关系应如何公开表达？
    
10. 询盘最终进入哪个邮箱或 CRM？
    
11. 是否需要老板和销售人员自行在后台更新内容？
    
12. 第一版是否只做英文，还是同步做西班牙语或阿拉伯语？

# 18. 下一步执行指令

建议交给 Codex 的第一个任务，不是立即生成网站，而是：

```text
请基于本仓库的现有资料，为 taicoev.com 完成项目初始化。

第一阶段只完成以下工作：

1. 创建标准仓库目录。
2. 创建 AGENTS.md。
3. 将现有产品、案例和应用资料整理为结构化知识库草稿。
4. 对所有参数、认证、案例、收益数字标注：
   - Verified
   - Needs Verification
   - Not Approved for Public Use
5. 生成：
   - brand-positioning.md
   - target-customers.md
   - product-priorities.md
   - sitemap.md
   - first-release-pages.md
   - open-questions.md
6. 暂时不要生成正式网站页面。
7. 不得编造任何缺失信息。
8. 每个结论注明来源文件和页码。
9. 输出本阶段完成情况、风险和等待老板确认的问题。
```

等战略和知识库通过人工审核后，再开始：

```text
Astro初始化
→ GitHub
→ Cloudflare测试部署
→ taicoev.com DNS和HTTPS
→ 设计系统
→ 核心页面
```

这份 Handoff 的核心目标是：

> **先把 TAICO EV 的客户、价值和可信信息定义清楚，再用现代工程链路建设一个可持续迭代的海外 B2B 获客系统，而不是快速生成一个通用新能源模板站。**
