TAICO EV · Visual System Standard

Product Visual / Evidence Asset System 标准指南

用于 TAICO EV 官网 Homepage、Family、Solution、Product、Resources、Knowledge、Case Study 的统一图片生产、AI 生成、证据分级和页面使用规范。

参考：BESEN 首页 / Landing Page 目标：从“资料站”升级为“制造企业橱窗” AI 可生成场景，但 Evidence 必须分级

01. 核心结论

TAICO 目前的 Typography、Card、Grid 和信息结构已经较清晰；下一步不应继续增加装饰性 UI，而应补齐真实的 Product / Context / Capability / Evidence 四层视觉资产。
BESEN 值得学习的不是“大图”，而是用图片完成 PCCE：产品 → 场景 → 能力 → 证据。

02. BESEN 首页如何使用图片

Hero：先让用户“看懂行业”

首屏通过 EV、充电设备、停车/建筑环境，让用户几乎不读文字就知道产品类别和应用场景。

规则：首页 Hero 优先卖“场景中的产品”，不要只卖参数或抽象科技感。

Evidence Chain：图片本身承担销售任务

工厂、展会、安装、测试、包装、项目、OEM/ODM 等图片分别证明不同商业能力。

规则：每张图都要回答一个采购问题。

Brand Visual + Evidence Visual 混合

品牌图负责吸引和定位，真实证据图负责可信度。只做漂亮图会像广告，只做纪实图会像供应商目录。

视觉顺序对应采购认知顺序

你是谁→ 你卖什么→ 你能不能做→ 凭什么信

04. TAICO Product Visual 标准资产包

P1 Hero Product

3/4 角主视觉、统一光线、统一比例。用于 Product / Family / Selector。

P2 Front

正面标准图。用于型号比较、产品卡片、参数页。

P3 Side / Back

接口、接线、安装、线缆管理等结构信息。

P4 Detail

屏幕、RFID、connector、急停、外壳、指示灯等局部。

P5 Engineering

Front / Side / Back / Dimensions / Mounting Points。

P6 Installation

墙装、立柱、停车场、车库等真实安装或 Reference-Locked 场景。

05. Scenario Visual 场景库

Residential

住宅、车库、Wallbox、EV。

Apartment

地下停车、多枪位、配电与负载管理。

Workplace

办公园区、员工停车、白天充电。

Commercial

商场、公共停车、多个充电位。

Fleet

Van / Truck、Depot、集中充电。

Installer

配电箱、施工人员、安装过程。

原则：Solution Page 的图要先表现“应用场景”，产品只是场景的一部分。

Case Study、认证、工厂、测试、客户项目不能用 AI 伪造。 AI 可以辅助清理背景、构图、统一风格，但不能把不存在的事实包装成真实 Evidence。

07. AI 图片使用规范

F1 · Exact Product

真实摄影 / CAD / 3D Render。外观 100% 一致。

F2 · Reference-Locked AI

真实产品作为 reference，AI 只扩展环境、光影、场景。

F3 · Conceptual

纯概念图，不出现可识别具体型号。

推荐流程

真实产品 PNG / 3D→ 锁定比例 / 接口 / Logo→ AI 生成环境→ 人工 QA
使用场景AI 是否适合要求
Homepage Hero适合Reference-Locked，产品一致
Solution Hero适合场景真实、技术逻辑合理
Product Detail谨慎优先真实摄影 / Render
Factory / Testing不用于伪造必须真实
Case Study不用于伪造必须真实项目

08. Evidence Level 分级

L0 Decorative

渐变、抽象背景、概念图。

L1 Render

真实产品的 3D / Studio Render。

L2 Real Product

真实产品摄影，证明产品存在。

L3 Operational Evidence

真实工厂、测试、安装、项目、客户、Shipment。

网站长期方向：减少 L0 依赖，增加 L2 / L3 占比。

11. SEO 图片规则

  • AI 图片本身不会因为“AI 生成”自动导致 SEO 降权；重点是相关性、可信度、页面质量和用户体验。
  • 使用 WebP / AVIF，Hero 控制文件体积。
  • 固定 width / height，避免 CLS。
  • 文件名语义化，例如 residential-ev-charging-taico.webp。
  • alt 描述画面真实内容，不把 AI 概念场景写成真实项目。
  • 真实 Case、Factory、Certification 的图片和正文应绑定可验证事实。

13. Visual Evidence Flywheel

每一次研发、生产、测试、发货、安装都应产生可复用视觉资产，再反哺 Website / SEO / Sales / Social。

14. 最终执行原则

  1. 先定义图片任务，再生产图片。 每张图必须对应 Product / Context / Capability / Evidence 中至少一个角色。
  2. AI 负责补“橱窗层”，真实素材负责“证据层”。
  3. 产品一致性优先于画面漂亮。 具体型号必须 Reference-Locked 或使用真实 Render。
  4. Landing Page 不使用同一种 Hero。 不同页面的首图任务不同。
  5. Case、工厂、认证、测试不允许 AI 伪造事实。
  6. 所有图片进入 Asset Library，并带 Metadata。 让 Codex / Agent 可以自动检索和组装页面。
  7. 长期目标不是积累“更多图片”，而是积累“更多可验证 Evidence”。
